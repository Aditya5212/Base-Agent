# Base Agent — Architectural Roadmap & Task Spec (2026-11-08)

## 📌 Thread-Level Scoping and Isolation for Knowledge Ingestion & Retrieval

### 1. Context & Motivation
Currently, knowledge base documents and vector chunks are scoped exclusively at the user level (`user_id`). 
When users upload documents via `POST /api/v1/documents/upload`, the documents are stored in the user's global knowledge base:
- Document record: `documents.user_id = <user_id>` (with no thread association).
- Storage key: `documents/{user_id}/{doc_id}_{filename}`.
- Vector store metadata: `filter_dict = {"user_id": user_id}`.
- LightRAG workspace: `user_workspace(user_id)`.

While thread assets (uploaded images and media files) support thread scoping (`threads/{thread_id}/...`), documents ingested into the RAG vector store and knowledge graph do not yet support **thread-level isolation**.

### 2. Goals & Scope
1. **Thread-Scoped Document Uploads**: Allow documents to be uploaded directly into an active conversation thread (`thread_id`), isolating them to that specific conversation.
2. **Dual-Layer Retrieval Scoping**:
   - **Thread Strict**: Search only documents explicitly uploaded to the current thread.
   - **Thread + User Global (Hybrid)**: Prioritize thread-scoped documents while allowing fallback to the user's global knowledge base.
3. **Workspace Isolation**:
   - Hybrid vector store: Tag chunks with both `user_id` and `thread_id`.
   - LightRAG: Route thread-scoped documents to `thread_workspace(user_id, thread_id)` ensuring zero graph leakage across conversations.
4. **Cascade Lifecycle Management**:
   - When a thread is purged via `DELETE /api/v1/chat/memory/{thread_id}`, automatically cascade delete all associated thread-scoped documents, document chunks in PGVector, R2 storage objects, and LightRAG workspace data.

### 3. Detailed Architectural Specification

#### A. Database Schema Updates
```sql
-- Migration revision: alembic/versions/YYYYMMDD_HHMM_document_thread_scoping.py

ALTER TABLE documents 
ADD COLUMN thread_id VARCHAR(128) NULL,
ADD CONSTRAINT fk_documents_thread_id FOREIGN KEY (thread_id) REFERENCES threads(id) ON DELETE CASCADE;

CREATE INDEX ix_documents_user_thread ON documents(user_id, thread_id);

-- Optional: Add thread_id to document_chunks for direct indexed SQL filtering
ALTER TABLE document_chunks
ADD COLUMN thread_id VARCHAR(128) NULL;

CREATE INDEX ix_document_chunks_thread_id ON document_chunks(thread_id);
```

#### B. Storage Hierarchy
- **User Global Documents**: `documents/{user_id}/global/{doc_id}_{filename}`
- **Thread-Scoped Documents**: `documents/{user_id}/threads/{thread_id}/{doc_id}_{filename}`

#### C. API Endpoints Contract Updates

##### 1. `POST /api/v1/documents/upload`
Add optional form parameter `thread_id: str | None = Form(default=None)`:
```python
@router.post("/upload")
async def upload_document(
    file: UploadFile = File(...),
    thread_id: str | None = Form(default=None, description="Optional conversation thread ID for session-isolated documents"),
    preset: str = Form(default="balanced"),
    index_graph: bool = Form(default=False),
    ...
):
```
- If `thread_id` is supplied:
  - Verify thread ownership (`verify_thread_ownership(db, thread_id, effective_user_id)`).
  - Associate `doc.thread_id = thread_id`.
  - Pass `thread_id` to `process_document_pipeline`.
  - If `index_graph=True`, route LightRAG ingestion to `thread_workspace(effective_user_id, thread_id)`.

##### 2. `GET /api/v1/documents`
Add query parameter `thread_id: str | None = Query(default=None)`:
- `thread_id=None`: Returns all documents for user (both global and thread-scoped).
- `thread_id="global"`: Returns only global documents.
- `thread_id="<uuid>"`: Returns documents scoped specifically to that conversation thread.

##### 3. Search & Retrieval (`retrieve_node` and `hybrid_document_search`)
When querying inside a thread:
```python
# Thread-aware metadata filter
if thread_id and thread_scoped_only:
    filter_dict = {"user_id": user_id, "thread_id": thread_id}
elif thread_id:
    # Filter matches either thread documents or global documents
    filter_dict = {
        "user_id": user_id,
        "$or": [{"thread_id": thread_id}, {"thread_id": None}]
    }
else:
    filter_dict = {"user_id": user_id, "thread_id": None}
```

##### 4. Thread Deletion Cascade (`DELETE /api/v1/chat/memory/{thread_id}`)
Update `delete_thread_memory` in `app/services/thread_service.py`:
- Fetch all documents with `Document.thread_id == thread_id`.
- For each document:
  - Delete raw file in Cloudflare R2: `await r2_storage_service.delete_file(doc.r2_key)`.
  - Delete vector embeddings in PGVector: `await delete_documents_by_metadata({"document_id": str(doc.id)})`.
  - Delete LightRAG workspace: `await (await get_provider("lightrag", thread_workspace(user_id, thread_id))).purge_workspace()`.
- Thread row deletion automatically cascade-deletes `documents` and `document_chunks` via foreign key `ON DELETE CASCADE`.
